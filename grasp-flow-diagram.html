Por que existe esta FSM

  • Evita que grupos CPRO/SAI aparezcan en Top MCV.
  • Evita que reparacion/ejection intente rescatar grupos que no deben existir.
  • Hace que warmup, elbow, GRASP y Excel usen la misma lista saneada.

Reglas de ingesta

  • ReglaGrupoTieneProgramacion
  • ReglaIgnorarGrupos
  • No evalua profesores ni horarios laborales.

Semantica actual: S_ijh forma el yeso base de afinidad; penalty talla el top K con geometria diaria y carga academica real. Alpha ya no decide sobre S_ijh puro, sino sobre scoreRcl.

Top K

  • Primero se recolectan candidatos que pasan FSM.
  • Se ordenan por S_ijh descendente.
  • Solo a esos K se les pide penalty real.

Alpha

  • umbral = max - alpha * (max - min)
  • Se aplica sobre scoreRcl.
  • El elegido se sortea entre candidatos filtrados.

PenaltyObservedCache: valores reales y cache exacto

sequenceDiagram
    participant G as GreedyOrchestrator
    participant V as ViabilidadPenalizacionCarga
    participant C as PenaltyObservedCache
    participant R as Redis
    participant P as Python backend

    G->>V: evaluarCandidatoAsync(grafo, eco, grupo)
    V->>V: construir payload exacto observado
    V->>C: getOrFetch(payload, context)
    C->>C: key = PenaltyObserved:v1:sha1(payloadExacto)
    C->>C: buscar LRU memoria
    alt hit memoria
        C-->>V: total_penalty real
    else miss memoria
        C->>R: GET key exacta
        alt hit Redis
            R-->>C: total_penalty real persistido
            C-->>V: total_penalty real
        else miss Redis
            C->>C: esperar turno por concurrencia limitada
            C->>P: POST /get_horario_penalty_finetuned
            P-->>C: total_penalty real
            C->>R: SET key exacta
            C->>C: guardar en LRU
            C-->>V: total_penalty real
        end
    end
    V-->>G: penaltyRaw + viabilidadPenalty

Key exacta

  • PenaltyObserved:v1:${sha1(payloadExacto)}
  • No deduplica por eco + horario.
  • No fusiona dias ni geometria diaria.

Payload

  • eco
  • horario del candidato predicho
  • ueas_asignadas_actuales
  • horarios_asignados_actuales
  • uea_prediccion

Errores duros

  • Timeout por intento configurable.
  • Retries configurables.
  • Watchdog si no completa ninguna request.
  • Sin mock, sin baseline, sin formula fallback.

Operacion, comandos y cuidados

Comando GRASP productivo

  • cd .\frontend-react
  • $env:NODE_OPTIONS="--max-old-space-size=4096"
  • npx tsx .\solution\greedy\testIngestaML.ts

Variables penalty

  • PENALTY_ML_BASE_URL
  • PENALTY_ML_TIMEOUT_MS
  • PENALTY_ML_CONCURRENCY
  • PENALTY_ML_WATCHDOG_MS
  • PENALTY_LRU_MAX_ENTRIES

Logs actuales

  • Todos los asignados de fase 1 salen en debug_grasp_fase1.json.
  • Incluye ecoElegido, penaltyRaw, viabilidadPenalty y scoreRcl.
  • Los JSON existentes deben regenerarse corriendo GRASP.

Estado de decisiones

Produccion: usar ejecutarAsync(). Esta ruta exige ViabilidadPenalizacionCarga con PenaltyObservedCache real.
No fallback: si Redis no tiene la key exacta y Python no responde tras retries, la ejecucion falla. Esto es intencional para afinar con datos productivos reales.
Costo: cada grupo evalua penalty para los top K candidatos por S_ijh. Redis persistente amortiza corridas posteriores, pero la primera corrida puede ser lenta.
